# レポート形式

チャットに直接出力する。ファイル保存はユーザーの明示的な同意を得てから行う。

## 出力テンプレート

```markdown
# Kuroco セキュリティ設定チェック結果

| | |
|---|---|
| 対象サイト | {site}.g.kuroco.app |
| サイト前提 | 会員限定サイト（Step 1 でユーザーが回答した内容をそのまま記載） |
| 実施日時 | 2026-08-01 14:30 JST |
| 接続 | Admin MCP `/x/all/readonly`（読み取り専用） |
| 対象カテゴリ | A, B, C, D, E（F/G/H は今回のスコープ外） |
| 設定変更 | **なし**（読み取りのみ実行） |

## サマリー

要対処 3件（HIGH 2 / MEDIUM 1）、要検討 2件、問題なし 11件、手動確認 4件。

最も優先すべきは B1（管理画面のIP制限が無効）と C1（ログインロック未設定）。
いずれも管理画面への総当たり攻撃に直結する。

## 要対処

### [HIGH] B1: 管理画面のアクセス制限(IPアドレス) が無効

- **現在値**: 無効
- **推奨値**: 有効化し、オフィス/VPNのIP・CIDRを登録
- **影響**: 任意のIPから管理画面ログインを試行できる。C1（ログインロック未設定）と組み合わさると総当たり攻撃が成立しやすい
- **根拠**: `{実際に呼んだツール名}` のレスポンス（該当フィールド名: `{実フィールド名}`）
- **対処**: [環境設定] → [管理画面] → 「管理画面のアクセス制限(IPアドレス)」を有効にしてIPを登録
- **参考**: kuroco-docs `management/management-screen`（元ページのslug。同梱ファイルは Grep で slug を検索して特定する）

### [HIGH] C1: ...

## 要検討

### C5: パスワードの有効期限日数が未設定

- **現在値**: 未設定
- **判断材料**: 定期変更を求めない運用方針であれば未設定で問題ない。社内規程で定期変更が必須の場合のみ設定する
- **確認したいこと**: 貴社のパスワード運用規程

## 問題なし

| ID | 項目 | 確認した値 |
|----|------|-----------|
| A1 | APIセキュリティ方式 | Cookie |
| A3 | CORS_ALLOW_ORIGINS | `https://example.com` のみ |

## 手動確認が必要な項目

Admin MCP から設定値を取得できなかった項目。管理画面で確認してほしい。

| ID | 項目 | 確認先 | 取得できなかった理由 |
|----|------|--------|-------------------|
| E1 | 静的アクセストークンの有効期限 | [API] → 対象API → [セキュリティ] | 発行済みトークンの本数・有効期限を返す読み取りツールが存在しない（認証方式が `static_token` / `privileged_static_token` かどうかは `api-list` で取得できる） |
| F1 | ステージング環境のBasic認証 | リポジトリの `kuroco_front.json` | Kuroco側の設定ではないため |

## 本チェックの範囲

本レポートは管理画面で設定できる項目のレビューであり、以下は対象外。

- 前後処理・カスタム関数・バッチ処理のコードの安全性
- フロントエンド実装の脆弱性
- 実際に攻撃が成立するかの検証（脆弱性診断・ペネトレーションテスト）
```

## 書き方のルール

| ルール | 理由 |
|--------|------|
| **重大度順に並べる** | 対処の優先順位がそのまま伝わる |
| **「現在値」には実際に取得した値を書く** | 推測値・デフォルト値を書かない。取得できなかったなら「手動確認」に回す |
| **「根拠」に実際に呼んだツール名とフィールド名を書く** | 検証可能にする。例示のフィールド名を使い回さない |
| **トークン・シークレット・パスワードの実値は書かない** | レポート自体が漏洩経路になる |
| **重大度を既定から変えたら理由を書く** | 「公開データ専用APIのため HIGH → 問題なし」のように |
| **「手動確認」を省略しない** | 未確認を「問題なし」に混ぜると監査結果が実態より安全に見える |
| **「セキュリティ上問題ありません」と断定しない** | 「本チェックリストの範囲では要対処なし」と範囲を明示する |
| **指摘が0件でも手動確認と範囲は必ず書く** | 0件の意味を読み手が正しく解釈できる |

## 件数が多い場合

要対処が10件を超える場合は、サマリーで HIGH のみを列挙し、
MEDIUM / LOW は表形式（ID・項目・現在値・対処）に圧縮してよい。
その場合も手動確認リストは省略しない。
