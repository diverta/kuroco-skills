# Claude.ai Desktop専用の接続準備パッチ

このスキルは既存のkuroco-app-builderとkuroco-frontend-integrationに追加して使う。既存スキルのファイルを書き換えず、Claude Code、Codex、Claude.ai Webや他の実行環境へ自動適用しない。

## コネクタが未接続の場合

最初に[接続時の短い案内](references/connector-guidance.md)を読む。利用者には、Kuroco側のCIMD設定、Claude側のコネクタ登録、今回の作業に必要な権限の順で案内する。人間の操作待ちでは、その操作と完了後の一言だけを伝えて停止する。設計表、仮定、採点、中間報告、技術用語の講義を添えない。

## 準備会話と構築会話を分ける

1. 準備会話では、Claudeは対象サイトと権限を確認し、Kurocoの一時保存先へ実際に通信する。サイト制作、ZIP作成、ファイル送信、デプロイは行わない。手順とUI案内は[接続準備](references/connection.md)を読む。
2. 通信を拒否された場合、Claudeは利用者または組織の管理者に、設定画面で行う操作を説明する。Claude自身は組織設定を変更しない。
3. Claudeは構築用の新しい会話へ貼る引き継ぎ文を作る。利用者がすぐ構築を始められるよう、依頼内容と対象サイトを省略せずに書く。新しい会話で必ず通信できるとは断定しない。
4. 構築会話では、Claudeは引き継いだ対象サイトと権限を確認し、保存先への通信を再確認する。成功後は既存の構築スキルへ進む。準備を再び最初から繰り返したり、さらに別の会話への移動を無条件に要求したりしない。

## 適用条件

- Claude.ai DesktopからKurocoFrontへの直接デプロイを利用する場合だけ適用する。GitHub連携だけの場合は通信設定を求めない。
- ホスト名は対象サイトについてKurocoが返した情報から取得する。別サイトの値や固定したリージョンを流用しない。
- モデルに見える許可ドメイン一覧を通信成功の証拠にしない。ファイルを送らない実通信で判定する。
- Team向けの操作案内を個人プランへ流用しない。個人プランの設定手順は未検証であり、今後更新する対象として扱う。
- 利用者には、誰が何をどこへ送るのか、どの文字列をどの入力欄へ入れるのかを具体的に説明する。

## 利用者への説明

通信設定の案内は、短い状況説明、ドメイン追加の操作、新しいチャットでの再開方法と理由に絞る。[接続準備](references/connection.md)の短い案内例を使う。
社内の検証経緯、スキルを探す実況、宅配便などの比喩、HTML・JSONの解説、コードの逐行説明は、利用者から求められない限り出力しない。非エンジニア向けとは、技術の講義ではなく、次に行う操作が分かる説明をすることである。
管理者への依頼文は、利用者が設定を変更できない場合だけ提示する。引き継ぎ文は操作案内と分け、次のClaudeが必要とする情報を残す。認証・権限・既存公開内容の上書き確認は省略しない。

## 検証範囲

2026-09-25、利用者から、Team環境で許可ドメイン追加後の新しい会話における通信確認、ZIP保存、プレビュー、本番デプロイとブラウザ表示の成功が報告された。共有された途中経過では制作とZIP作成後にこのスキルが読まれており、制作前の自動適用は確認できていない。短くした案内文についても、利用者から確認済みとの報告を受けた。通信確認、ZIPの保存、デプロイ完了と、スキルの適用タイミング・案内品質は分けて記録する。
