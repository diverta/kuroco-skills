# コネクタ接続時の案内

接続仕様と権限の判断にはkuroco-admin-mcpを使う。画面操作の正本は[公式の接続手順](https://kuroco.app/ja/docs/reference/mcp-client-configuration/)。以下はClaude.ai Desktopで利用者に説明する順序と長さを定める。

## 最初にKuroco側の設定を案内する

コネクタが未登録の場合は、CIMDが無効と断定せず、利用者に状態を確認してもらう。コネクタ登録だけを案内してKuroco側の前提を省略しない。

案内例：

> まず、ClaudeをKurocoに接続するための設定を確認してください。
>
> 1. Kuroco管理画面の「Admin MCP」を開き、接続に使う認可サーバーの設定を開いてください。通常は「Admin MCP (default)」です。
> 2. 「クライアント ID メタデータドキュメント（URL クライアント ID）」を有効にして保存してください。これがClaudeとの接続に使うCIMDの設定です。すでに有効なら変更は不要です。
>
> 保存できたら「できた」と教えてください。次にClaude側の接続を案内します。

画面に該当項目がない場合、実画面を確認して案内する。公式の別経路は「外部システム連携 → ID連携 → OAuth Authorization Server」。個別の認可サーバーを使っているサイトではdefaultに勝手に切り替えない。設定変更は利用者または管理者が行う。

## 次にClaude側の接続を案内する

Kuroco側の確認後、利用者にClaudeのコネクタ追加画面を開いてもらい、Admin MCP情報ページから取得したURLをコピーする操作、ログイン、権限選択、許可の順に案内する。URLを利用者に手で組み立てさせない。画面名が異なる場合は実画面を確認する。

今回必要な権限を先に判断し、利用者に全種類の説明表を見せず、選ぶ項目と理由を一文で伝える。

- 会員グループや汎用バッチを作る依頼：`mcp:admin`が必要。案内例は「今回は役割ごとの権限グループも作るため、『全権限』（mcp:admin）を選んでください」。スーパーユーザーが承認する必要がある。画面の選択肢が違う場合や承認できない場合は管理者へ依頼する。
- API定義の作成までで、上記操作がない依頼：`mcp:tools.all`。これを「制限のない全権限」と説明しない。
- 読み取りだけの依頼：読み取り用の権限を使う。すべての接続で全権限を要求しない。

最後は「接続できたら教えてください。こちらで接続先と操作権限を確認します」で止める。接続後にwhoamiで実効権限を確認する。表示上の接続済みや選択したラベルだけで成功としない。

## 混同しないこと

Claudeのコード実行環境からのHTTP通信と、コネクタによるAdmin MCP接続は別経路。コード実行環境がhost_not_allowedを返しても、それだけでコネクタも接続不能とは判断しない。コネクタ接続の案内前に、APIドメインの外部通信許可や特権静的トークンを既定の解決策として求めない。
新しい会話が必要な場合だけ、確認できた状況に応じて短く理由を説明し、依頼内容を引き継ぐ。「ファイルは必ず消える」「途中では必ずツールが使えない」と未確認の制約を断定しない。
時刻・エラー全文・採点・詳細設計は記録に残し、利用者が求めたときか最終報告で提示する。人間の操作待ちの返信には混ぜない。
