# KurocoFront以外の公開先

ユーザーが KurocoFront 以外（Codex Sites / Vercel / Netlify / v0 / Lovable など）を指定した場合、または **SSR / ISR が必要で KurocoFront では実現できない**場合に読む。
実装パターン（フレームワーク・認証・CORS・XSS対策）は公開先によらず [SKILL.md](../SKILL.md) と同じ。ここでは**公開先が変わることで追加で確認が必要になる点だけ**を扱う。

## 実装前に確認する軸

ホスティング側の仕様は変化するため、機能の一覧ではなく次の軸で確認する。軸は仕様が変わっても変わらない。

| 軸 | 確認すること | 満たせない場合 |
|---|---|---|
| **SSR / ISR の実行可否** | サーバー実行が必要な構成か。KurocoFrontを離れる主な理由はこれ。ただし[SSR/ISRが本当に必要かの切り分け](../SKILL.md#ssrisrが本当に必要かの切り分け)を先に通す。**会員制の画面はSSRにしても利点が出ない**（サーバー側fetchにセッションCookieが乗らない） | SSGまたはSPAで足りるなら KurocoFront に戻す |
| **CORS許可オリジン** | 公開先のドメインを管理画面 [API] → [セキュリティ] → [CORS設定] の `CORS_ALLOW_ORIGINS` に登録できるか。プレビューごとにURLが変わる公開先では登録しきれないことがある | 実APIを直接呼べない。モックのままにするか KurocoFront にする |
| **Cookie認証のドメイン** | Cookie認証を使う場合、フロントとAPIがサブドメイン違いに揃うか（[サードパーティCookie問題](../SKILL.md#サードパーティcookie問題spaのcookie認証)） | 動的アクセストークン方式に切り替えるか KurocoFront にする |
| **独自ドメイン** | 運用するドメインを割り当てられるか | 継続運用には使えない。試作に限定する |
| **公開URLの恒久性・公開範囲** | そのURLが運用URLなのか、レビュー用の一時URLなのか。誰まで見えるのか | 恒久運用の要件があるなら KurocoFront にする |
| **秘密情報の置き場** | サーバー側で秘密情報を保持できるか、ブラウザに露出するか | 下の「実APIへ接続しない条件」に該当 |

Codex Sites を選んだ場合は、実装時点で利用可能な Sites 構築・ホスティングスキルと現在の製品仕様を読み、上の軸を埋めてから進める。過去の挙動を固定仕様として扱わない。
なお **Codex Sites（`chatgpt.site`）は ChatGPT の通常チャットからは操作できず、Work モードまたは Codex での実行が前提**になる（[公開先の決定](../SKILL.md#実行環境の制約codex-sites)）。

## 実APIへ接続しない条件

次のいずれかが必要なら、この公開先から Kuroco の実APIへ接続しない。

- 特権トークンや管理資格情報
- ブラウザへ公開できない秘密情報
- Kurocoへの書き込み権限
- 上の軸で安全性を説明できない認証フロー

この場合はモックでの試作に限定するか、KurocoFront へ変更する選択肢を提示する。

## 公開時

- 公開範囲は製品UIが示す内容をユーザーに確認する。推測して説明しない。
- 公開前に、対象・閲覧範囲・実データを使うかどうかを確認する。
- 引き渡し時に、使用したデータがモックか実APIか、公開範囲、確認できた制約を明記する。
