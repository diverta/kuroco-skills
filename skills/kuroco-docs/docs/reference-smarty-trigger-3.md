# カスタム処理に利用できるトリガと変数の一覧

> 元ページ: `reference/trigger-variables` ｜ 公式ページ: https://kuroco.app/ja/docs/reference/trigger-variables/
> 概要: カスタム処理を使用して、特定の処理の途中で独自の処理を実行することができます。

[カスタム処理](/ja/docs/management/function/)を使用して、特定の処理の途中で独自の処理の実行ができます。

例えば、「トリガー」フィールドに「コンテンツの追加後」を選択し、対象のコンテンツ定義を選択することで、特定のコンテンツ定義IDのコンテンツが追加された場合に処理を実行できます。

![Image from Gyazo](https://t.gyazo.com/teams/diverta/e14a9237c423e6a11a09a00deac4e998.png)

利用できる変数はテンプレートにあらかじめ変数がアサインされていることを指し、返り値はテンプレートにアサインされている場合にシステムが処理の結果として認識する変数であることを指します。

選択したトリガーにより利用できる変数が異なります。トリガー毎の利用できる変数をまとめましたので下記ご参照ください。

## コンテンツ
### コンテンツの表示（管理画面）
注意：このトリガーは「スーパーユーザー」でログインしている場合も実行されますが、`$filters`・`$disable_columns`・`$default_columns` は「スーパーユーザー」には適用されません（`$errors`・`$form_data` は適用されます）。
コンテンツ一覧画面、コンテンツ編集画面表示時に呼び出されます。
コンテンツ定義IDごとに設定できます。

#### コンポーネントの指定方法
- トリガー : 「コンテンツの表示（管理画面）」を選択
- テキストフィールド : トリガーの対象とするコンテンツ定義IDを入力

#### 利用できる変数
| 変数名 | 型 | 説明 |
| :--- | :--- | :--- |
| $ext_config | Object (ext_config) | コンテンツ拡張設定 |
| $topics_id | Integer | コンテンツID（新規作成時は空、既存コンテンツ編集時はIDが入る） |

#### 返り値
| 変数名 | 型 | 説明 | サンプル |
| :--- | :--- | :--- | :--- |
| $filters | Object | フィルター条件 | `{"filter":"subject contain SomeText","order:"subject=ASC"}`<br/>詳細は[Filter検索のパラメータ](/ja/docs/reference/filter-query/)を参照ください。 |
| $disable_columns | Array | 非表示にしたい項目キー | ["ymd", ... ] |

| $form_data | Object | コンテンツ編集画面を開いた際の初期値 | コンテンツの新規作成時に初期値を設定する<br/><pre><code>&#123;if !$topics_id&#125;<br/>  &#123;assign var=form_data.ext_1 value='abc'&#125;<br/>&#123;/if&#125;</code></pre> |

### コンテンツの表示(API)
注意：このトリガーによるフィルターは「スーパーユーザー」でのAPIリクエスト時には適用されません。
APIでコンテンツを取得する際に呼び出されます。コンテンツ一覧・詳細のAPIエンドポイントに加え、コンテンツに紐づくファイルへのアクセス（IMG_URL / API_URL経由）時にも呼び出されるため、ファイルダウンロードのアクセス制御にも利用できます。
コンテンツ定義IDごとに設定できます。

#### コンポーネントの指定方法
- トリガー : 「コンテンツの表示(API)」を選択
- テキストフィールド : トリガーの対象とするコンテンツ定義IDを入力

#### 利用できる変数
| 変数名 | 型 | 説明 |
| :--- | :--- | :--- |
| $ext_config | Object (ext_config) | コンテンツ拡張設定 |

#### 返り値
| 変数名 | 型 | 説明 |
| :--- | :--- | :--- |
| $filter | String | フィルター条件<br/>詳細は[Filter検索のパラメータ](/ja/docs/reference/filter-query/)を参照ください。 |
| $errors | String<br/>Array<br/>Object | エラーメッセージ |
| $http_code | Integer | HTTPステータスコード（400, 401, 404） |

#### APIリクエストパラメータの`filter`との違い
`$filter` はAPIリクエストパラメータの `filter` と同じ書式ですが、以下の点が異なります。

- **追加条件として適用**: リクエストパラメータの `filter` を上書きするのではなく、別のWHERE句として追加（AND）されます。API呼び出し側が指定した `filter` と、このトリガーの `$filter` の両方が同時に適用されます。
- **全カラムでフィルター可能**: リクエストパラメータの `filter` はエンドポイント設定の許可カラムに制限されますが、トリガーの `$filter` は全カラムを対象にフィルターできます。
- **スーパーユーザーの自動バイパス**: このトリガーのフィルターはスーパーユーザーのAPIリクエスト時には自動的にスキップされます。
- **ファイルアクセスにも適用**: コンテンツに紐づくファイルへのアクセス時にも呼び出されるため、ファイルのアクセス制御が可能です。
- **アクセス拒否**: `$http_code` に 400/401/404 を返すことで、フィルターではなくアクセス自体をブロックできます。

#### 使用例

ログインメンバーが自分の投稿したコンテンツのみAPI経由で取得できるようにする例：

```text
{if $smarty.session.member_id}
    {assign var="filter" value="member_id = `$smarty.session.member_id`"}
{else}
    {assign var="filter" value="member_id = 0"}
{/if}
```

この例では、ログイン中のメンバーは自分が作成したコンテンツのみ取得でき、未ログイン時は `member_id = 0` により該当コンテンツが存在しないため、コンテンツは返されません。

### 承認待ちコンテンツの表示（管理画面）
注意：このトリガーは「スーパーユーザー」でログインしている場合も実行されますが、絞り込みに関する返り値（`$filters`・`$trigger_filter_group_ids`・`$approvalflow_id`・`$authorized_status`・`$can_approve`・`$my_applications`）は「スーパーユーザー」には適用されません（`$errors` は適用されます）。
管理画面の承認待ちコンテンツ一覧画面（`/management/topics/topics_waiting_for_approval_list/`）の表示時に呼び出されます。また、コンテンツ一覧画面の承認待ちボックスも同じ画面のデータを取得しているため、その件数・一覧にもこのトリガーの結果が適用されます。API経由で承認待ちコンテンツを取得する場合には呼び出されません。
承認待ちコンテンツ一覧画面はコンテンツ定義を指定せずに複数のコンテンツ定義をまたいで表示することもできるため、このトリガーはコンテンツ定義IDを指定して設定することはできません（「共通」としてのみ設定できます）。表示対象のコンテンツ定義IDは `$topics_group_ids` で取得できるため、コンテンツ定義ごとに処理を分けたい場合はカスタム処理内で `$topics_group_ids` を判定してください。

#### コンポーネントの指定方法
- トリガー : 「承認待ちコンテンツの表示（管理画面）」を選択

#### 利用できる変数
| 変数名 | 型 | 説明 |
| :--- | :--- | :--- |
| $topics_group_ids | Array | 表示対象のコンテンツ定義ID |
| $ext_config | Object (ext_config) | コンテンツ拡張設定 |

#### 返り値
| 変数名 | 型 | 説明 | サンプル |
| :--- | :--- | :--- | :--- |
| $filters | Object | フィルター条件<br/>`order` には一覧画面の詳細検索の並び順で選択できる項目を指定できます（`topics_id`、`slug`、`ymd`、`subject`、`inst_ymdhi`、`update_ymdhi`、および並び替えに対応した拡張項目）。 | `{"filter":"subject contains \"テスト\"","order":"subject=ASC"}`<br/>詳細は[Filter検索のパラメータ](/ja/docs/reference/filter-query/)を参照ください。 |
| $trigger_filter_group_ids | Array | 表示対象とするコンテンツ定義ID<br/>ログインユーザーが権限を持つコンテンツ定義IDのみが適用されます。権限のあるIDが1件もない場合は無視されます。 | [1, 2] |
| $approvalflow_id | Integer<br/>Array | 絞り込む承認フローID | 3<br/>[3, 4] |
| $authorized_status | Integer<br/>Array | 絞り込む承認ステータス（0: 承認待ち、10: 承認完了） | [0] |
| $can_approve | Boolean | true の場合、ログインユーザーが承認できるコンテンツのみを表示します。 | true |
| $my_applications | Boolean | true の場合、ログインユーザーが申請したコンテンツのみを表示します。 | true |
| $errors | String<br/>Array<br/>Object | 表示エラー | "エラーメッセージ"<br/>[ "エラーメッセージ", ... ]<br/>`{ "項目名": "エラーメッセージ", ... }` |

:::note
`$trigger_filter_group_ids`、`$approvalflow_id`、`$authorized_status`、`$can_approve`、`$my_applications`、および `$filters.filter` を返した場合、画面で指定された検索条件よりもトリガーの返り値が優先されます。`$filters.order` は、画面で明示的な並び順が指定されていない場合にのみデフォルトの並び順として適用されます（画面で並び順が指定されている場合はそちらが優先されます）。
:::

#### 使用例

ログインユーザーが承認できる承認待ちコンテンツのみを表示する例：

```text
{assign var="can_approve" value=true}
```

タイトルに特定の文字列を含む承認待ちコンテンツのみを表示する例：

```text
{assign_array var="filters" values=""}
{assign var="filters.filter" value="subject contains \"テスト\""}
```

コンテンツ定義ID 1 の承認待ちコンテンツ一覧を表示している場合のみ、自分の申請のみに絞り込む例：

```text
{assign var="target_group_id" value=1}
{if $target_group_id|in_array:$topics_group_ids}
  {assign var="my_applications" value=true}
{/if}
```

## 認証

### ログインロジックの追加

このトリガーは、標準の認証処理（ID/パスワード認証、SAML、SSO等）とは別に、カスタム処理テンプレートによる独自の認証ロジックを追加するためのものです。

ログイン時、システムは複数の認証方式を順番に試行します。標準の認証方式（ID/パスワード、SAML、SSO等）がすべて失敗した場合に、このトリガーで設定したカスタム処理が実行されます。カスタム処理テンプレート内で返り値の変数をアサインすることで、ログインの可否やログイン対象のユーザーを制御できます。

このトリガーは管理画面のログインとAPIのログインの両方で発火します。

#### コンポーネントの指定方法
- トリガー : 「ログインロジックの追加」を選択

#### 返り値
|変数名 |型   |説明   |
| :--- | :--- | :--- |
| $login_email | String | メールアドレスまたはログインID。ログイン対象のメンバーを特定するために使用します。 |
| $login_member_id | Int | メンバーID。`$login_email`の代わりにメンバーIDで直接指定することもできます。 |
| $login_save | Bool | ログイン状態を維持する |
| $is_login | Bool | ログインを許可する。`true`にするとログインが許可されます。`false`または未設定の場合、ログインは失敗します。 |
| $custom_search_ids | Int[] | セッションにセットする[カスタムメンバーフィルター](/ja/docs/management/custom-member-filter/)のID配列（オプション）。通常、ログイン時にはメンバーの情報をもとに「そのメンバーが条件に合致するカスタムメンバーフィルター」のIDリストが自動算出されます。この変数を指定すると、自動算出の代わりに指定したIDリストがそのままセッションにセットされます。これにより、本来はフィルタ条件に合致しないカスタムメンバーフィルターのIDを強制的に付与でき、そのフィルターで制限されたAPIエンドポイントへのアクセスを許可できます。未指定の場合は通常通り自動算出されます。 |

# カスタムメンバーフィルターで利用できるカスタム処理の変数

> 元ページ: `reference/variables-for-custom-function-available-in-custom-member-filters` ｜ 公式ページ: https://kuroco.app/ja/docs/reference/variables-for-custom-function-available-in-custom-member-filters/
> 概要: api

カスタム処理で独自に定義したフィルターをカスタムメンバーフィルターで使用できます。  
カスタムメンバーフィルター編集画面で、カスタム処理タブを開き、適応するカスタム処理を選択してください。  

![Image from Gyazo](https://t.gyazo.com/teams/diverta/5f48f5b56b4de44126d5a658ad0bc6d1.png)

## カスタムメンバーフィルターの変数

|変数名|種別|説明|
|:--|:--|:--|
|$params|入力変数|カスタムメンバーフィルターに設定したJSONが渡されます。|
|$data|出力変数|`$data.result`(真偽値)または、`$data.filter`(フィルタ用の文字列)のいずれかを設定します。<br/>両方指定された場合は `$data.result` が優先されます。|

### $params
カスタムメンバーフィルターに設定したJSONが渡されます。

![Image from Gyazo](https://t.gyazo.com/teams/diverta/f03ac047f714c5a3f2d2287f47926274.png)

### $data.result

0/1 または false/true を指定します。

|値|説明|
|:--|:--|
|0, false|すべてのメンバーを出力しない|
|1, true|すべてのメンバーを出力する|

:::info
`$data.filter`が同時に指定された場合は、`$data.result`が優先されます。
:::

### $data.filter

フィルタ用の文字列を指定します。  

例：`member_id in [2,4,5]`

形式は、Member::listのエンドポイントにかけるフィルタと同様です。  
利用できる条件や記述は[Filter検索のパラメータ](/ja/docs/reference/filter-query/)を参照してください。

## カスタム処理の例
カスタム処理内で`{date}`のSmartyプラグインや`$smarty.session.member_id`を利用することで、カスタムメンバーフィルターを利用した日付や、メンバーで結果が変わるフィルターを作成できます。  

カスタム処理の例をいくつか紹介します。

### $data.result の利用例

毎月5日に全てのメンバーに出力し、5日以外は誰も出力しないフィルター。

```smarty
{assign_array var="data" values=""}
{date var='day' time='now' format='d'}
{if $day == 5}
    {append var="data" index="result" value=true}
{else}
    {append var="data" index="result" value=false}
{/if}
```

### $paramsと$data.resultの利用例

毎月、カスタムメンバーフィルターで指定された日に全てのメンバーに出力し、それ以外は誰も出力しないフィルター。

**カスタムメンバーフィルター編集画面のJSON**  
```json
{"special_day": 5}
```

**カスタム処理**  
```smarty
{assign_array var="data" values=""}
{date var='day' time='now' format='d'}
{if $day == $params.special_day}
    {append var="data" index="result" value=true}
{else}
    {append var="data" index="result" value=false}
{/if}
```

### $data.filter の利用例

メンバーの拡張項目に「業種（business_type）」を定義し、カスタムメンバーフィルターを利用したログインメンバーと同一の「業種」のメンバーを出力するフィルター。

```smarty
{assign_array var="data" values=""}

{assign_array var="method_params" values=""}
{assign_array var="request_params" values=""}
{append var="method_params" index="member_id" value=$smarty.session.member_id}
{api_method
    var='member'
    model='Member'
    method='details'
    version='1'
    method_params=$method_params
    request_params=$request_params
}
{if $member}
    {append var="data" index="filter" value="business_type=`$member.details.business_type.key`"}
{else}
    {append var="data" index="result" value=false}
{/if}
```
